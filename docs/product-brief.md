# Product brief

## Problem

"Readers also liked" style features are everywhere, and teams spend a lot of time choosing algorithms. The inputs, like which of a person's items to start from, get less attention, and a test that only measures hits can hide recommendations that all point at the same bestsellers.

## Users

- **Product managers for discovery and personalisation** who decide what to build and test.
- **Data scientists** who want a quick, honest baseline before building a bigger model.
- **Hiring managers** reading this portfolio, who want to see how I set up and read an offline test.

## Goals

1. Compare personalised methods with a bestseller list on the same readers and the same hidden books.
2. Find which choices matter most, starting with how much of the reader's history to use.
3. Measure variety as well as hits.
4. Separate the easy cases (series) from the rest.

## Non-goals for 0.1.0

- An online A/B test or click data.
- Deep learning models.
- New readers with no ratings.

## Success measures

A portfolio piece, so there is no usage target. It succeeds if a PM could use it to decide what to test first in a real "readers also liked" feature.
